# Development guide

WE Time Tracker is, a desktop time tracker for freelancers (Electron 31 + Vite 5, plain JavaScript ES modules, no framework). Repository: github.com/JaffarSk24/WE-Time-Tracker. Start from origin/main at commit c5d111a or later. Feature work happens on separate branches that are merged one by one after every screen is checked on a real Mac. Stay inside your feature, keep changes to shared files small and additive, and do not refactor code the feature does not need.

## Map of the code

- electron-main.cjs: main process. Data file userData/we-tracker-data.json (read/save helpers, daily backups), tray (menu-bar timer: formatTrayElapsed, updateTrayTitle, rebuildTrayMenu, initTray, stopTimerFromTray), app:// protocol, createWindow/showMainWindow, Google Drive IPC, updates IPC, before-quit upload. preload.cjs exposes bridges window.weStorage, weTimer, weUpdates, weGDrive (keep all of them, only add).
- gdrive-sync.cjs + gdrive-utils.cjs: Google Drive sync (OAuth PKCE loopback, hidden appDataFolder file). INVARIANTS, never weaken: on launch only pull; upload only on close/quit/Sync button and only after checking the cloud; change detection by content hash; when both sides changed, mergeData() merges every top-level array of records by id (newer copy wins per record, deletions from state.deleted applied). Any new data you add must be either a field on an existing record or a top-level array of records with unique string ids, so sync merges it automatically.
- updater.cjs + update-utils.cjs: in-app updater. Do not touch.
- src/app.js: entry. Imports Lucide icons by name (two lists: the import and the usedIcons object; add every new icon to BOTH, on a new line), initNavigation (nav items with data-target = section id), initModalUX (Esc/backdrop closes .modal-overlay, Enter clicks .btn-primary), updateGlobalUI, store.subscribe re-render.
- src/store.js: single source of truth (class Store, export store). State: clients[] (each with payments[]), projects[], timeLogs[], settings, activeTimer, deleted{} (tombstones), savedAt. Methods: addClient/updateClient/deleteClient, getProjects/addProject/updateProject/deleteProject, getRate, addPayment/deletePayment/getPayments, logAmount, getBilledAmount, createAutoPayment/reverseAutoPayments (a log marked paid creates a linked auto payment; invariant: every paid log is covered by a payment), getClientBalance, getTimeLogs/addTimeLog/updateTimeLog/deleteTimeLogs/restoreTimeLogs/setLogsPaid, startTimer/pauseTimer/resumeTimer/stopTimer/cancelTimer, getSettings/updateSettings, exportData/importData/clearAllData, markDeleted/unmarkDeleted. GENERIC API for new data: getCollection(name), upsertRecord(name, record), patchRecord(name, id, patch) (works for clients/projects/timeLogs too), deleteRecord(name, id). Use these instead of adding many new store methods. saveState() stamps savedAt and persists.
- src/utils.js: logDurationMs(log) (worked time, respects pauses), billableHours(ms) (to the minute, minimum 1 minute, NEVER round up to blocks), escapeHtml, toLocalDatetimeString, localDayKey, dayKeyToLocalDate, formatDurationHMS, formatDurationShort, fillSelect, csvCell.
- src/i18n.js: translations { ru: {...}, en: {...} }, t(key, params) with {placeholders}, translatePage() for data-i18n attributes.
- src/timer.js: Timer view (timer widget, today's entries with a play button to continue, manual entry form). src/dashboard.js: Dashboard (stat cards, Chart.js charts by project/client, activity chart with period select). src/clients.js: Clients & Projects view (client cards, project cards, client/project modals, payments modal). src/reports.js: Reports & Logs (filters, summary, bulk mark paid/delete with undo, daily grouped list, edit log modal, CSV/JSON export). src/settings.js: Settings (language, theme, export/import/reset, Google Drive section, updates section). src/banners.js, src/updates.js: notices and updates. src/toast.js: showToast(message, {type, actionLabel, onAction, duration}).
- index.html: sidebar nav, the five view sections (timer-view, dashboard-view, clients-view, reports-view, settings-view), modals at the end. src/style.css: one stylesheet with CSS variables, dark and light themes (body.light-theme or similar, check before styling), classes .card, .btn .btn-primary/.btn-secondary/.btn-danger/.btn-sm, .form-group, .modal-overlay/.modal-content/.modal-header/.modal-actions, .data-action-box (settings rows).
- Phone web app (npm run build:web -> dist-web/, npm run dev:web; published at https://jaffarsk24.github.io/WE-Time-Tracker/app/ by .github/workflows/pages.yml): web.html + src/web/ (main.js entry, app.js screens, auth.js browser Google sign-in, drive.js Drive requests, sync.js sync engine with the desktop rules, cloud.js triggers, week.js pure week numbers, i18n-web.js its texts, web.css its styles), public-web/ (manifest and icons), scripts/vite-web-plugins.js (service worker, web.html as index.html, and the virtual module 'virtual:gdrive-utils' that lets the web app import gdrive-utils.cjs unchanged, so both apps share one copy of the sync rules). It reuses store.js and utils.js; the desktop entry, bundle and electron-builder build do not include any of it. The OAuth web client id comes from VITE_GOOGLE_WEB_CLIENT_ID (repository variable GOOGLE_WEB_CLIENT_ID in the Pages workflow).
- tests/: Vitest (store.test.js, gdrive-utils.test.js, gdrive-sync.test.js, update-utils.test.js, updates.test.js). npm test, npm run lint (ESLint), npm run build (Vite) must all pass.

## Rules (a branch that breaks them is not merged)

- Do not lose or change any existing behaviour that your task does not ask to change. Existing features must keep working exactly as before.
- All user-visible text through i18n keys in BOTH ru and en. Add your keys as one block at the END of each language dictionary, introduced by a comment line naming your feature. Russian texts natural, short.
- In ANY text you write (UI strings, code comments, commit messages, docs): no em dash or en dash characters at all; use commas, colons, parentheses or a plain hyphen. No notes about which tools wrote the code, no Co-Authored-By trailers.
- Code comments and commit messages in English. Commit messages describe the user-visible change.
- Dates and times shown to people in LOCAL time: use toLocalDatetimeString / localDayKey / toLocaleDateString, never toISOString().slice for display or day grouping.
- Money: use billableHours(logDurationMs(log)) * rate, keep the existing formatting style of amounts (two decimals and the euro sign as the app shows them today).
- User input into the DOM only via textContent or escapeHtml. Toasts instead of alert(). No CDN or network resources at runtime: bundle everything via npm/Vite.
- CSS: append your styles at the END of src/style.css under a comment header naming your feature; use the existing CSS variables so both dark and light themes work; layouts must not break at 900px window width (the minimum) or at 1440px.
- index.html: add new modals right before the comment "Initialize Application Modules"; add new markup inside the view you work on.
- New logic goes into new modules under src/ (one per feature) wherever possible, with pure functions covered by Vitest tests in tests/.
- Work in small commits and push your branch after each meaningful step, so nothing is lost if you are stopped. Before the final push: npm test, npm run lint and npm run build must pass. If a headless browser is available, run npm run dev (web mode keeps data in localStorage) and check your screens; otherwise say so.
- Push only your own feature branch. Never push to main, never create tags or releases, never open a pull request into main.
- When done (or stopped), report: branch and last commit, what was implemented per item, files changed, test/lint/build results, anything left undone and any decision the owner should know about.
